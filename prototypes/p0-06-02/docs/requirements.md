# SA动态二维码用户端聚合页原型需求

## 目标

服务助手先在移动端选择可投活动并生成动态二维码；用户扫码后进入客户侧H5聚合页，在同一页面查看该SA本次选择的全部活动，并以尽量少的操作完成当前可参与活动。

## 页面范围

- SA选择活动页：自动带出SA与标准门店，按三级展示可投活动，支持全选、逐项勾选和生成动态二维码。
- SA选活动详情页：从可投活动卡片进入，展示活动基本信息、活动规则、关联卡券、关联权益和互斥关系。
- 二维码有效期抽屉：SA生成或重新生成前，从后台候选时长中选择固定时长或“长期有效（至活动有效期）”，默认值预选。
- 二维码结果页：展示二维码、sceneId、生成/失效时间、有效时长、配置版本、活动数量和冻结活动清单。
- SA分享海报编辑页：固定嵌入当前二维码、来源SA姓名/工号、来源门店和有效期，支持编辑标题、副标题和扫码引导语并实时预览。
- SA分享海报预览页：展示最终海报，支持返回继续编辑，并提供保存到相册和分享给客户的演示反馈。
- 我的SA数据—概览：展示本人扫码、活动参与、发券、核销、转化率、核销率和趋势数据。
- 我的SA数据—活动：活动列表、活动详情、脱敏参与记录列表和参与记录详情。
- 我的SA数据—卡券：券模板列表和简版卡券生命周期详情。
- 活动聚合页：SA来源提示、默认VIN、普通/组合活动连续列表、活动复选和底部一键参与；不向扫码用户展示活动等级分区或等级标签。
- 组合活动状态：未绑车与已绑车两个可评审状态，始终只展示一张大活动卡片。
- VIN选择弹层：展示已绑定车辆并切换当前执行VIN；每次只执行一个VIN。
- 一键参与结果弹层：统一反馈直接发券和自动抽奖结果。
- 绑车/认证离开提示：等级不足活动可发起升级，但完成后不回跳当前聚合页。
- 生命周期状态：重新生成确认、旧码失效/过期结果、SA无可投活动和提交时活动下线的部分未处理结果。

## 核心规则

1. SA可选活动必须已发布、允许进入SA二维码、门店范围匹配、执行方式有效且不是后台统一推券。
2. 当前SA工号、姓名和标准门店自动读取且不可修改。
3. SA可选择全部或部分活动；生成时冻结活动ID集合和版本，每次生成唯一sceneId。
4. 页面只展示当前SA二维码冻结的活动ID范围，但范围内活动全部展示。
5. 页面加载时根据oneID、当前VIN和各活动准入表达计算状态。
6. 当前可参与活动默认勾选；已参与和等级不足活动不可勾选。
7. 已参与活动继续展示并标记“已参与”，不隐藏。
8. 用户扫码聚合页不展示号码级、绑车级、认证级分区标题或等级标签；系统内部仍按三级准入规则计算活动状态和参与唯一键。
9. 号码级参与主体为oneID；绑车级参与主体为当前VIN；认证级参与主体为当前oneID与VIN的一对一认证关系。
10. 多VIN用户加载默认VIN；系统一定存在默认VIN，不使用绑定车辆列表第一辆兜底。
11. 切换VIN后重新计算绑车级和认证级活动状态；号码级活动状态不随VIN改变。
12. 点击底部“一键参与”后同时执行全部已勾选活动；不同活动准入校验节点可分别执行。
13. 直接领券类活动即时发券；抽奖类活动自动抽奖，只反馈中奖或未中奖结果。
14. 不演示发券失败。
15. 后台统一推券类活动不允许SA选择，因此不会出现在聚合页。
16. 绑车或认证完成后不回跳；用户需要重新扫描SA二维码进入。
17. SA本人移动端数据只展示sourceSaId为本人的记录，手机号和VIN脱敏，oneID不展示且不可导出。
18. 移动端报表与后台SA活动报表、SA卡券报表使用同一统计口径。
19. 重新生成二维码后，旧码阻断新的扫码；已建立的旧扫码会话可继续，但提交时重新校验。
20. 活动在页面加载后下线时，仅拦截该活动，其他有效活动继续执行并汇总反馈。
21. SA移动端和用户端的活动类型标签统一显示“领券”或“抽奖”，不显示“直接领券”或“自动抽奖”。
22. SA选择活动时可点击活动主体查看详情，勾选框仍只负责加入或移出二维码范围。
23. 活动可配置互斥组和互斥主体口径；号码级按同一账号校验，绑车级按当前VIN校验，认证级按当前认证关系校验。
24. 同一互斥组内多个活动同时可参与时，只默认勾选一个；用户勾选另一个时自动取消原选择并提示互斥原因。
25. 若同一参与主体已参加互斥组中的任一活动，其余互斥活动显示“互斥已参与”并不可选择；一键参与提交前再次校验互斥关系。
26. 卡券不存在“已使用”口径；移动报表统一展示“已核销”和“核销率”，核销率=核销成功券实例数÷发放券实例数。
27. SA选活动详情的基本信息不展示主办方；“执行方式”字段改名为“领券方式”。
28. SA侧页面统一使用蓝色主视觉，用户扫码后的活动聚合页继续沿用原有红色视觉。
29. SA卡券列表与详情中的卡券生效状态统一显示“已生效”，不显示“发放中”。
30. 组合活动在用户端只展示一张大活动卡片，不向用户展示留存、流失、复购等人群标签。
31. 未绑车时组合活动卡片可见但不可勾选，卡券区域整体不渲染，不展示“卡券内容待解锁”等占位文案，仅保留去绑车入口。
32. 绑车并取得当前VIN后，系统返回该VIN命中的全部子活动，并在原卡片内汇总展示所有对应卡券和权益；切换VIN后刷新同卡片内容。
33. 组合活动参与唯一键为“组合活动ID + VIN”；一次参与可同时执行当前VIN命中的多个子活动，且组合整体只记一次参与。
34. 同一VIN命中多个子活动时，命中的卡券与权益全部发放；不阻断、不记为异常，不设优先级和执行顺序。
35. 二维码有效时长只能从后台候选项选择；固定时长范围5分钟至1天，并增加“长期有效（至活动有效期）”，不支持自由输入；抽屉默认勾选后台默认值。
36. 取消有效期抽屉不生成二维码；重新生成时再次选择时长。
37. 二维码场景保存durationMode、durationMinutes、generatedAt、expiresAt和configVersion；长期有效时durationMode=ACTIVITY_END、durationMinutes为空，expiresAt取冻结活动中最晚结束时间；后台参数变更不影响既有二维码。
38. 组合活动在SA选择、二维码冻结快照、用户聚合卡片、详情与参与结果中优先展示“组合活动展示名称”；未配置时回退原组合活动名称。
39. 组合活动可见/可分享必须同时满足独立SA投放有效、组合活动启用、当前SA所属门店命中适用门店；未配置门店等同全部门店。
40. 未命中当前SA门店的组合活动不出现在SA正常选择页，也不能进入本次二维码冻结范围；门店范围不改变子活动或卡券核销门店。
41. 二维码长期有效不代表活动永不过期；各活动结束或下线后仍实时过滤，冻结范围内全部活动结束后二维码到期。
42. 二维码生成后，SA可制作活动分享海报；海报必须嵌入当前二维码、来源SA姓名/工号、来源门店及二维码有效期。
43. SA可选择系统模板或上传自定义海报底图；上传支持JPG/PNG、单张不超过10MB，建议3:4比例，系统仍统一叠加当前二维码、来源SA/门店和有效期。
44. SA只可编辑海报标题、副标题和扫码引导语，不能修改二维码、sceneId、来源SA或门店；文案分别限制20、36、24个字符。
45. 海报与当前sceneId绑定；重新生成二维码后，旧海报中的旧二维码同步失效，但已建立扫码会话仍沿用原二维码生命周期规则。
46. 海报面向客户展示，不呈现“活动范围已锁定”等内部冻结、配置或技术状态文案；该规则仅在二维码快照和后台留痕中体现。

## 视觉基准

- `qa/source-mobile-card-center.jpg`
- 沿用现有客户端白色页头、浅灰背景、白底卡片和紧凑信息层级；SA侧使用蓝色主按钮，用户活动聚合页保留红色主按钮。
- 目标视口390 × 844，无横向滚动，底部主操作持续可见。

## 不在本原型范围

- 后台SA活动报表与SA卡券报表。
- 真实登录、绑车、认证、发券、抽奖及卡包接口。
- 发券失败、并发或网络异常流程。
