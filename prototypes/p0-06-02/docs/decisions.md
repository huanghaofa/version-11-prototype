# 产品决策

- 组合活动对外名称统一由 displayName 非空值优先、空值回退 name 计算，SA端和扫码用户端不直接展示原后台名称。
- SA活动池先取独立投放有效对象，再校验组合活动状态和当前SA门店范围；三项缺一不可。
- 未配置适用门店归一为全部门店；指定范围仅按门店ID判断，门店名称只用于展示。
- 适用门店只控制SA查看与分享，子活动参与和卡券核销仍沿用各自主配置。
- 单独建立客户侧H5原型，不修改已交付的后台原型。
- 页面标题采用“专属活动”，避免对用户展示“归因”等后台术语。
- 聚合页展示SA选择范围内的全部活动；状态分为可参与、已参与、需绑车、需认证。
- 用户扫码聚合页隐藏号码级、绑车级、认证级分区标题和卡片等级标签；三级模型只用于内部准入、唯一键与校验，不作为客户文案展示。
- 可参与活动默认勾选，用户可取消；底部只保留一个统一“一键参与”按钮。
- 多VIN通过页头车辆选择器切换，每次仅执行当前VIN。
- 一键参与结果在一个底部弹层中反馈，不为每个活动增加中间确认。
- 对需绑车/认证活动，卡片内直接提供升级入口；点击后提示将离开且不回跳。
- 视觉以现有“我的卡券/领券中心”移动端页面为基准；SA侧改为蓝色主视觉，用户扫码后的活动聚合页保留日产红。
- 原型默认进入“选择活动”，SA选择页与用户聚合页共用同一移动端视觉体系。
- SA身份、工号和门店只读展示；不提供切换来源身份或门店能力。
- 可投活动按三级分区，支持全选和逐项取消；原型默认全选，便于演示完整路径。
- 生成结果页展示真实可扫描PNG二维码及冻结快照，并提供“模拟用户扫码”串联客户侧页面。
- 二维码候选有效时长和默认值由后台配置；固定时长合法范围5分钟至1天，同时支持“长期有效（至活动有效期）”。
- 聚合二维码选择长期有效时，截止到所选活动中最晚结束时间；活动自身结束或下线后仍实时过滤。
- 二维码结果页提供分享海报入口；SA可编辑营销文案，但二维码、sceneId和来源SA/门店固定不可改。
- 海报支持系统模板和SA上传自定义底图两种来源；上传底图后仍由系统叠加标准二维码与来源信息。
- “我的SA数据”使用概览、活动、卡券三页签；活动和卡券通过列表进入详情，不增加复杂筛选表单。
- SA移动端明细仅展示本人数据，手机号/VIN脱敏，oneID隐藏，不提供导出入口。
- 二维码重新生成先二次确认，并提供旧码失效扫码状态用于评审。
- 无可投活动、二维码失效和活动提交前下线以页面状态或结果弹层承载，不增加新的业务菜单。
- SA选择活动卡片主体可进入活动详情，复选框与详情点击互不干扰。
- 用户端互斥活动采用“同组单选切换”：默认保留排序靠前且可参与的活动，勾选另一活动时自动替换并提示，不增加中间确认弹层。
- 互斥关系在页面加载、VIN切换、用户改选和一键参与提交前均校验；已参加同组活动时其余活动直接锁定。
- 卡券数据只使用发放、激活、核销、失效等口径；不再展示已使用和使用率。
- SA选活动详情精简基本信息，不展示主办方；活动动作字段统一命名为“领券方式”。
- SA卡券状态使用“已生效”，不再使用“发放中”。
- 组合活动作为一个大活动进入SA选择和用户聚合页，用户端始终只展示一张卡片。
- 组合活动绑车前整体隐藏卡券区域，不展示待解锁占位框；绑车并匹配VIN后在原卡片汇总展示所有命中券；参与唯一键为组合活动ID + VIN。
- 同一VIN命中多个子活动时全部执行，不阻断、不记为异常，不设优先级和顺序。
- 组合活动仅生成一条参与主记录，发放明细按命中子活动保留。
- 二维码重新生成不沿用旧选择，重新打开时长抽屉并默认选择后台默认值。
- 原型交付必须支持直接双击`index.html`通过file协议预览；HTTP仅作为可选调试方式。
- 上级统一静态入口串联SA选择活动、本人数据和用户聚合页。
