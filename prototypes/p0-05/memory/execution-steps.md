# 执行步骤

## 步骤 01：建立活动中心壳与领域数据

### 需求来源
- `docs/requirements.md` 全局导航、页面范围和独立项目要求。

### 目标
通过统一导航进入总览及各业务模块，所有页面从 `mock/data.js` 读取集中数据。

### 文件
- `index.html`
- `assets/css/global.css`
- `assets/css/app.css`
- `config/nav.json`
- `mock/data.js`
- `js/common.js`
- `js/app.js`
- `js/nav.js`

### 输入
- `docs/requirements.md`
- `docs/decisions.md`
- `memory/business-rules.md`

### 工作
- 建立接近 DFN 活动中心的顶部栏、侧边导航、内容区、抽屉、弹窗和 Toast。
- 配置总览、积分配置、活动管理、奖励记录和对账路由。
- 集中定义积分配置、活动、奖项、发放记录和对账任务 Mock 数据。

### 验收
- 入口页通过 HTTP 打开。
- 导航至少包含 8 个叶子路由且可以切换。
- 总览展示核心规则、统计和流程。
- 本地资源无阻塞 404，JS 无语法错误。

### 验证
- `node --check js/app.js js/common.js js/nav.js mock/data.js`
- HTTP 200、导航 DOM、console 和资源检查。

### 验证技能
- `prototype-verifier`
- `playwright-cli`

### 依赖
- 无。

### 失败处理
- 资源或导航失败回到本步骤修复；结构不符回到 S5/S6。

## 步骤 03：实现活动选择与认证级联动

### 需求来源
- D-003、D-006、活动发布规则。

### 目标
在活动新增/编辑页证明“仅认证级可选积分、活动只选择配置、发布锁定版本”。

### 文件
- `js/app.js`
- `mock/data.js`
- `assets/css/app.css`

### 输入
- `docs/requirements.md`
- `memory/business-rules.md`

### 工作
- 实现准入表达切换与积分奖励可用性联动。
- 实现直接奖励和抽奖奖池两种选择方式。
- 选择积分配置后只读展示积分数量、预算号、业务主场景、业务子场景和有效期。
- 实现发布校验和活动详情快照。

### 验收
- 号码级/绑车级无法选择积分并有明确提示。
- 认证级可以选择已启用配置，不出现积分参数输入框。
- 抽奖奖项可分别选择卡券或积分配置。
- 发布后展示配置 ID、版本和预算快照。

### 验证
- 切换准入表达，检查积分选项状态。
- 选择配置、切换玩法、增加奖项和发布反馈。
- 检查详情快照字段。

### 验证技能
- `prototype-verifier`
- `playwright-cli`

### 依赖
- 步骤 02。

### 失败处理
- 联动错误留在本步骤修复；页面范围变化回到 S7。

## 步骤 05：恢复独立预算配置与预算快照

### 需求来源
- 用户确认恢复原有预算配置；成本中心继续隐藏；业务主/子场景严格沿用卡券中心。

### 目标
在积分配置中独立维护预算，并让活动、发放和对账只读引用预算快照。

### 文件
- `js/app.js`
- `assets/css/app.css`
- `docs/requirements.md`
- `docs/decisions.md`
- `docs/interaction.html`
- `memory/business-rules.md`

### 工作
- 列表恢复预算号、预算使用率、额度和预警状态。
- 新增/编辑配置恢复预算号、预算额度和预警阈值校验；已用/剩余预算只读。
- 详情展示完整预算配置；活动仅展示预算号快照，不提供预算输入。
- 发放记录和对账记录固化并展示预算号；成本中心及积分场景码不展示。

### 验收
- 新增、编辑、查看三个配置状态均包含预算配置。
- 预算额度必须为正整数，预警阈值必须为 1-100 的整数。
- 活动页面无预算输入框，只显示配置预算号快照。
- 每笔积分发放和对账任务可追溯预算号。
- 页面不存在成本中心和积分场景码输入或展示。

### 验证
- JS 语法检查、全路由 DOM/console/资源检查。
- 预算表单必填、范围校验和主/子场景级联检查。
- 桌面端与 390px 移动端页面检查。

### 验证技能
- `prototype-verifier`
- `playwright-cli`
- `verification-before-completion`

### 依赖
- 步骤 02、步骤 03、步骤 04。

### 失败处理
- 页面或交互错误留在本步骤修复；预算接口字段不清写入 open item。
