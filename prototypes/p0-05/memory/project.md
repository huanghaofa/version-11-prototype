# 项目记忆

## 项目定位

- 项目名称：活动中心积分奖励原型
- 创建日期：2026-07-22
- 类型：无构建步骤的静态前端原型
- 入口：`index.html`

## 产品目标

将积分作为活动中心的标准奖励类型，在严格依赖认证级准入的前提下，完成积分配置、活动引用、VIN 发放、记录追踪和对账异常的闭环演示。

## 目标用户

- 活动运营：创建积分配置、配置活动奖励、查看发放结果。
- 审核人员：审核积分配置、关注预算和成本归属。
- 运营支持/财务：查看积分流水、预算使用和对账差异。

## 核心页面列表

- 总览、积分配置列表、积分配置表单、积分配置详情/版本。
- 活动奖励配置、活动详情快照。
- 奖励发放记录/详情、积分对账/异常处理。

## 核心用户路径

积分配置创建并审核启用 → 认证级活动选择积分配置 → 发布锁定配置版本 → 活动最终成功 → 查询默认卡并锁定 VIN → 调用积分系统 → 成功/查询/补偿 → 对账。

## 主要数据对象

- 积分配置、积分配置版本、活动、奖励规则、奖项、奖励发放记录、积分流水、对账任务、异常任务。

## 交付方式

独立可维护的静态 HTML 原型项目，包含 Mock 数据、交互脚本、业务文档、项目记忆、可编辑标注和验证记录。

## 已确认假设

- 所有活动类型具备积分奖励扩展能力，但仅认证级活动允许实际选择。
- 积分按默认卡 VIN 发放，活动侧不让用户手工选择 VIN。
- 活动只引用已生效积分配置，不编辑积分参数。
- 积分系统已有发放、结果查询、冲正和对账接口。
- 预算余额以积分系统为准；原型不连接真实接口。
- 自动冲正不在本期范围。

## 目录结构

- `js/components/` — 可复用的 B 端公共组件（如高级搜索、弹窗、分页器）
- `js/pages/` — 具体的业务页面逻辑（如仪表盘、线索列表）
- `assets/css/global.css` — 全局 B 端设计规范与通用组件样式
- `assets/css/app.css` — 应用基础样式与布局
- `config/nav.json` — 菜单路由配置（唯一路由数据源，由 `js/nav.js` 动态渲染）
- `mock/data.js` — 全站 B 端模拟数据集与状态机
- `SKILL-evolve-b-prototype.md` — B 端原型迭代演进技能，可供 AI Agent 在后续开发中调用
- `tools/` — 开发辅助工具脚本

## 工作原则

- 先理解现有代码和业务逻辑，再修改。
- 非必要不修改现有板块内容。
- 业务、Mock、文档、记忆和标注工具分别维护。
