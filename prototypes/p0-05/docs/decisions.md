# 项目决策记录

## D-001 静态原型架构

使用 HTML、CSS 和原生 JavaScript，不引入构建工具，除非后续需求明确要求。

## D-002 积分配置与活动配置分离

积分数量、预算配置、业务主场景、业务子场景和有效期统一在“积分配置管理”中维护。活动内只选择配置，不允许重复编辑积分参数。预算配置包含预算号、预算额度和预警阈值；已用预算、剩余预算和预算使用率只读展示。成本中心继续隐藏；不单独配置积分场景码，业务场景严格使用卡券中心业务主/子场景。

业务主场景、业务子场景严格复用卡券中心的两级枚举和父子级联关系，本期在活动中心按卡券枚举写死，不新增积分专属场景：

- 售前营销 → 在线购车、节点营销、CAP活动、直播活动、区域活动、试驾、新车上市。
- 售后营销 → 维保活动、续保活动。
- 售后营销-上门取送车 → 取送车活动。
- 商城营销 → 会员商城(新)、新商城。

## D-003 准入表达硬门槛

只有准入表达为“认证级”的活动才能选择积分奖励。号码级和绑车级活动隐藏或禁用积分选项；如果已选积分后将准入改为非认证级，阻止保存和发布。

## D-004 默认卡 VIN

积分按用户默认卡对应 VIN 发放。首次生成奖励记录时锁定 VIN；查询、重试、补偿和对账均使用原 VIN，不因默认卡后续变化而切换。

## D-005 配置审批与版本

积分配置采用“草稿 → 待审核 → 已启用 → 已停用/已过期”。发布活动锁定配置 ID 和版本；已被发布活动引用的配置不能原地修改核心字段，需生成新版本。

## D-006 多奖励与抽奖奖池

一个普通奖励项选择一项积分配置。抽奖活动可创建多条奖项，不同奖项分别选择卡券模板或积分配置；一个活动可以引用多项积分配置。

## D-007 预算与成本字段处理

积分配置页面恢复独立预算配置，维护预算号、预算额度和预警阈值；预算使用情况以积分系统查询结果为准。达到预警阈值后提示，达到 100% 后停止新发放，但不改变已经生成的中奖或达标结果。活动页面只选择积分配置，预算信息只读展示；每笔积分发放记录必须固化预算号。成本中心继续隐藏，其接口必传性和默认来源在技术联调前确认。

## D-008 冲正范围

本期不实现自动冲正，仅在积分发放详情和数据结构中保留原流水号、冲正状态、冲正流水号和冲正原因。

## D-009 删除 C 端到账反馈

本期不建设或演示用户侧积分到账反馈页面，不定义发放中、成功或异常处理中的 C 端展示文案及消息通知策略。活动中心后台仍保留积分发放状态、结果查询、异常补偿和对账闭环。
