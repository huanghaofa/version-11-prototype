# 项目决策记录

## D-001 静态原型架构

使用 HTML、CSS 和原生 JavaScript，不引入构建工具，除非后续需求明确要求。

## D-002 业务分类口径

用户所说的“类型”是卡包业务分类，如“全部 / 商城”，不是代金券、折扣券等券种。

## D-003 VIN 共用券模型

同一 VIN 的多个有效关联人可以看到同一个券实例；后台同一次发券只生成一个 VIN 券实例，不按手机号生成共享副本。

## D-004 卡包承接方

卡包 H5 由卡券中心统一承接。本原型另起独立目录，不修改历史原型。

## D-005 原型默认分类

业务分类采用历史卡包证据中的完整集合：全部、购车、商城、维保、车联、取送车、试驾、加油、出行、影视、其他。分类顺序固定并支持横向滚动；后续如按用户类型动态排序，另行评审。

## D-006 分类与分组组合

“全部”同时展示手机号通用券和各 VIN 分组；选择“商城”等分类后，只保留命中分类且有数据的分组，不为每个分类制作一套独立页面。

## D-007 视觉方向

采用现代移动端卡包风格，红色作为品牌强调色，浅灰作为页面底色。原型数据只用于演示交互，不代表 SIT 实际数据。

## D-008 用户侧分组命名与车辆信息

- 原“手机号通用券”统一改名为“个人卡券”，技术归属仍为手机号/oneID。
- 车辆分组只展示车型名称和脱敏 VIN，不展示“2024款 经典舒适版”等年款、配置版本。

## D-009 券种与状态补充展示

- 业务分类仍为一级筛选；券卡内补充展示满减券、代金券、折扣券、权益券、服务券、兑换券、虚拟卡等券种。
- 增加“全部状态 / 可使用 / 待激活 / 已使用 / 已过期”状态筛选，与业务分类组合生效。
- Axure 后台状态“未领取”不直接暴露给 C 端，前台统一展示为“待激活”。
- 已使用和已过期不提供主操作；“激活超时”作为已过期的具体原因展示。

## D-010 码类操作区分

- 线下 VIN 券使用“出示核销码”，展示归属车型和脱敏 VIN。
- 第三方权益及虚拟卡使用“查看兑换码”，展示归属账号，支持复制兑换码；有卡号时同时展示卡号。

## D-011 核销码页面参照 Axure

- “出示核销码”不再使用底部弹层，改为独立移动页面。
- 页面结构参照 Axure“我的卡券-核销码（线下）_6”：顶部返回栏、券摘要、条形码、数字码、二维码和使用说明。
- 当前二维码和条形码为交互原型图形，不作为真实可扫验收依据。

## D-012 通用兑换券参照既有兑换券任务

- 将“通用兑换券”与第三方兑换码券区分：第三方券查看/复制兑换码；通用兑换券进入卡券中心在线选品兑换。
- 复用“通用兑换券原型_20260720”已确认的四步体验：券详情、选商品、确认兑换、兑换成功。
- 本原型演示5选2、同 SKU 两件、跨车联网履约/直邮/到店核销组合。
- 兑换单创建成功即核销卡券；履约与发货状态独立更新。

## D-013 卡包页头与个人卡券文案收敛

- Axure `我的卡券-全部_13` 的页头后直接进入业务分类和可用券列表，没有总券数、车辆头像和关联车辆数量摘要。
- 删除原型页头中的“全部状态 / XX张券 / 车辆头像 / X辆关联车辆”整块展示。
- 卡包默认状态由“全部状态”改为“可使用”；其他状态继续作为评审演示入口。
- 个人卡券分组只展示脱敏手机号，隐藏“与车辆无关”。

## D-014 车辆标识与共用提示收敛

- 默认车辆继续展示“默认车辆”，使用品牌红实心胶囊和勾选符号增强识别。
- 非默认车辆不展示“新能源”等能源类型标签。
- VIN 共用券的用户侧说明统一为“车辆有效关联人均可使用”，不再展示“查询和核销的是同一券实例”等后台实现表达。
