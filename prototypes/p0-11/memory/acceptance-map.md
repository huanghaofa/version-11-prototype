# 验收映射

> 将需求条目映射到可观察的验收标准和验证方式。

| Requirement ID | Requirement | Acceptance Criteria | Verification | Status |
| --- | --- | --- | --- | --- |
| R-001 | 原型项目可以本地运行 | 入口页通过 HTTP 正常打开，无阻塞错误 | 浏览器打开入口，检查 console 和资源请求 | Pass |
| R-002 | 新增“部分叠加互斥” | 选择新增方式时同时展示非空叠加、互斥名单 | 检查默认状态与切换交互 | Pass |
| R-002A | 历史规则兼容 | 方式 1–4 只展示对应单一配置；历史“无”仍可选择 | 逐项切换并检查可见配置 | Pass |
| R-003 | 独立维护指定券 | 两类弹窗分别维护目标券并回填同一张关系列表 | 打开弹窗勾选、取消并确认 | Pass |
| R-004 | 防止同一券双重关系 | 已在另一规则中的券不可重复选择并显示原因 | 在互斥弹窗检查已选叠加券状态 | Pass |
| R-005 | 阻止无意义组合 | 新增方式同券冲突不可保存；部分模式空集合不可保存 | 切换规则并触发保存校验 | Pass |
| R-006 | 沿用活动中心关系列表 | 页面包含活动/卡券页签、主券查询条件及既有列表列结构 | 导航至保客活动互斥关系并核对页面 | Pass |
| R-007 | 响应式可用 | 390px 视口无页面横向溢出，表格在自身容器滚动 | 浏览器调整为 390px 并检查 | Pass |
| R-008 | 两类关系支持批量导入 | 部分叠加券和部分互斥券均可从统一列表打开导入弹窗 | 检查列表操作入口和弹窗标题 | Pass |
| R-009 | 导入前预校验 | 结果区分可导入、已存在、不可导入，并展示逐行原因 | 加载示例文件并检查汇总与明细 | Pass |
| R-010 | 部分成功导入 | 确认后仅合并通过行，跳过和失败行不写入 | 确认导入后检查部分券数量和标签 | Pass |
| R-011 | 新方式写入卡券关系表 | 每张主券均展示对应叠加券和互斥券，关系字段明确 | 保存后核对统一配置表和互斥关系列表 | Pass |
| R-012 | 配置区展示主券 | 统一关系表包含主卡券 ID/名称；每条目标关系按全部主券展开 | 核对默认行数及导入后的主券关系数量 | Pass |
| R-013 | 配置表隐藏状态列 | 配置表表头和数据区均无状态列，其余字段与操作保持可用 | 核对表头、行数、导入和移除入口 | Pass |

## 规则

- 每个核心需求至少对应一条验收标准。
- 验收标准必须可观察、可验证。
- 不确定需求写入 `memory/open-items.md`，不要写入已确认验收项。
