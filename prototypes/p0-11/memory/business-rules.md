# 已确认业务规则

## 业务对象定义

- 活动主券：当前活动直接发放或关联的卡券。
- 目标券：与活动主券建立叠加/互斥关系的卡券。
- 部分叠加券：允许与活动主券组合使用的目标券，对应历史“指定叠加券”。
- 部分互斥券：不允许与活动主券组合使用的目标券，对应历史“指定互斥券”。
- 导入批次：用户一次上传的卡券 ID 清单及其预校验结果，未确认前不改变活动配置。

## 关键字段含义

- `activity_id + coupon_id`：规则定位键，不能只按卡券 ID 判断。
- 规则方式：历史“无”及四种业务方式，新增“部分叠加互斥”。

## 主要状态和枚举

- 原型规则方式：`none / allStack / allMutex / partialStack / partialMutex / partialBoth`。
- 历史方式不迁移；`partialBoth` 才同时启用 `stackCouponIds` 和 `mutexCouponIds`。
- 卡券状态：已发布且有效可选；已失效、未发布不可选。

## 权限或角色边界

- 活动中心负责活动内卡券关系配置和保存。
- 卡券中心提供卡券基础信息、发放/领取事实；不在本原型中维护售前叠加规则。
- 新商城按活动维度消费关系快照并计算可组合结果。

## 异常、空状态或边界规则

- 部分模式未选择任何券时不可保存。
- 仅在“部分叠加互斥”中，同一目标券不能同时出现在两组集合。
- 批量导入必须先按当前关系执行同样的跨规则、卡券状态和重复校验，不能绕过手工选择的禁用规则。
- 已在当前关系中的卡券标记为“已存在”并跳过，不重复写入。
- 同一批次中有错误行时，仍允许确认导入其余通过行，错误行不写入。
- 活动互斥命中时，不再以卡券叠加结果放行。
- 卡券互斥命中时优先返回不可组合。
- 三个关系列表均未命中时默认不可组合。
