# 项目记忆

## 项目定位

- 项目名称：活动中心卡券互斥叠加并行配置原型
- 创建日期：2026-07-29
- 类型：无构建步骤的静态前端原型
- 入口：`index.html`

## 产品目标

保留售后/保客活动原有卡券规则方式，并新增“部分叠加互斥”，让新增方式可同时维护两类关系且不影响历史数据。

## 目标用户

- 活动中心运营人员
- 产品、研发、测试评审人员

## 核心页面列表

- 保客活动编辑：选择兼容型规则方式；在一张卡券关系列表中维护关系。
- 保客活动互斥关系：沿用活动中心现有查询区和卡券关系表查看结果。

## 核心用户路径

- 进入活动编辑 → 选择规则方式 → 手工选择或批量导入部分券 → 在统一列表核对 → 保存 → 查看保客活动互斥关系。

## 主要数据对象

- 活动：活动 ID、名称、状态、触发方式、有效期。
- 活动主券：本活动发放/关联的卡券。
- 目标券：与活动主券建立叠加或互斥关系的外部卡券。
- 卡券关系：规则范围、指定券集合、最终生效类型。

## 交付方式

独立、无构建步骤的静态前端原型，通过本地 HTTP 打开。

## 已确认假设

- 活动中心售后规则与卡券中心售前叠加规则业务域隔离。
- 活动互斥优先于卡券互斥，卡券互斥优先于卡券叠加。
- 默认未命中任何关系列表时不可组合使用。
- 原型不改原 Axure 包。

## 目录结构

- `js/components/` — 可复用的 B 端公共组件（如高级搜索、弹窗、分页器）
- `js/pages/` — 具体的业务页面逻辑（如仪表盘、线索列表）
- `assets/css/global.css` — 全局 B 端设计规范与通用组件样式
- `assets/css/app.css` — 应用基础样式与布局
- `config/nav.json` — 菜单路由配置（唯一路由数据源，由 `js/nav.js` 动态渲染）
- `mock/data.js` — 全站 B 端模拟数据集与状态机
- `SKILL-evolve-b-prototype.md` — B 端原型迭代演进技能，可供 AI Agent 在后续开发中调用
- `tools/` — 开发辅助工具脚本
