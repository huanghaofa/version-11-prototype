# 活动中心卡券互斥叠加并行配置原型需求基线

## 项目目标

在不改变活动中心（售后）历史规则数据含义的前提下，新增“部分叠加互斥”规则方式，使同一活动可以：

- 与一组卡券叠加；
- 同时与另一组卡券互斥；
- 在保存前看清最终生效关系与冲突结果。

## 功能范围

- 在保客活动创建/编辑页展示“卡券组合使用规则”。
- 保留“与全部券叠加 / 与全部券互斥 / 部分叠加 / 部分互斥”四种历史业务方式，以及历史“无”。
- 新增第五种业务方式“部分叠加互斥”。
- 只有选择“部分叠加互斥”时，才允许在同一张卡券关系列表中同时维护叠加、互斥两类行。
- “部分叠加”和“部分互斥”分别对应历史“与指定券叠加”和“与指定券互斥”，仅调整界面文案，不改变数据含义。
- 指定券模式支持查询、筛选、勾选、跨筛选保留与已选结果回显。
- 指定叠加券和指定互斥券均支持批量导入。
- 批量导入支持模板下载、文件上传、导入前预校验、结果分类和错误明细。
- 确认导入时只合并校验通过的券；已存在的券跳过，不可导入的券保留原因。
- 同一目标券不能同时存在于指定叠加和指定互斥列表；选择时即时提示并阻止重复。
- 活动编辑页沿用活动中心列表风格，以单张关系表统一展示和维护两类关系。
- 活动编辑页的关系表同时展示主卡券 ID、主卡券名称；每条目标关系按当前活动的全部主券展开。
- 活动编辑页的关系表不展示“状态”列，避免无操作价值的冗余信息。
- “保客活动互斥关系”页沿用现有页签、查询区和列表列结构；新增方式产生叠加、互斥两类关系行。
- 保存时再次执行组合合法性、指定券必选和重复券校验。

## 非本期范围

- 不修改原始 Axure HTML。
- 不改活动互斥配置；活动互斥仍是独立维度且优先于卡券关系。
- 不设计卡券中心自身的售前叠加规则。
- 不定义真实接口字段、导入任务异步处理、导出历史和正式权限。
- 不确认门店、E3S、DMS 等非新商城用券场景是否复用本规则。

## 原型目标用户

- 活动中心运营人员：创建或编辑售后/保客活动并配置活动内卡券关系。
- 产品、研发和测试：评审双规则并行后的字段、校验和最终生效口径。

## 核心路径

1. 进入保客活动编辑页。
2. 查看活动已关联的主券。
3. 选择一种卡券组合规则方式。
4. 若选择部分规则，在选择弹窗中添加目标券；新增方式的两类结果统一回填到一张列表。
5. 或通过批量导入上传券 ID 清单，检查成功、跳过和失败明细后确认。
6. 在卡券关系列表中核对关系类型、目标卡券和来源活动。
7. 保存配置并进入“保客活动互斥关系”列表。

## 验收方向

- 原有四种业务规则方式及历史“无”能够按原含义回显，不要求历史数据迁移。
- 选择“部分叠加互斥”后，同一活动能同时保留非空的叠加规则和互斥规则。
- 选择其他任一历史方式时，只展示和保存该方式对应的单一规则。
- 指定叠加券与指定互斥券可分别维护，互不覆盖。
- 无意义或冲突组合会被即时阻止，并给出可理解的原因。
- 两类指定券都可进入批量导入，导入前可区分可导入、已存在和不可导入数据。
- 不可导入行不影响其他通过行确认导入，且可查看具体原因。
- 卡券关系列表能区分叠加/互斥类型，并显示主券、目标券、关系和来源活动 ID。
- 新增或批量导入目标券后，每张主券都新增对应关系行；移除目标关系时同步移除所有主券映射。
