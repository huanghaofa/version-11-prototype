# 项目决策记录

## D-001 静态原型架构

使用 HTML、CSS 和原生 JavaScript，不引入构建工具，除非后续需求明确要求。

## D-002 保留历史枚举并新增规则方式

原型保留旧的“无 / 全部叠加 / 指定叠加 / 全部互斥 / 指定互斥”数据含义，不改成所有活动都使用双字段。界面将“指定”展示为“部分”，并新增：

- `部分叠加互斥`

只有新增方式使用叠加券、互斥券两组部分名单；历史活动继续按旧值读取，避免批量迁移和兼容风险。

## D-003 组合合法性

- 新增“部分叠加互斥”允许同时维护两组目标券，但两个集合必须互斥。
- 历史四种业务方式只维护其对应的一种关系，不受另一隐藏名单影响。
- 新增方式中，目标券已在另一列表时，选择和导入均阻止并解释原因。

## D-004 规则边界

本原型只处理活动中心（售后）的卡券关系。活动互斥保持独立且优先；卡券中心售前叠加规则不纳入比较，也不存在两套规则之间的优先级。

## D-005 批量导入采用“预校验后部分成功”

- 导入对象是当前正在配置的部分叠加券或部分互斥券。
- 模板以卡券 ID 作为必填唯一键，卡券名称只用于辅助核对。
- 上传后先分类为“可导入 / 已存在 / 不可导入”，运营确认后仅合并可导入行。
- 不可导入原因包括：另一关系已选、卡券不存在、卡券状态不可用、文件内重复、卡券 ID 缺失。
- 原型默认单次最多 1000 行，真实上限和文件大小限制待研发确认。
